binary-sentinel

Static PE and ELF triage in pure JavaScript: headers, sections, entropy, imports, imphash, packer hints, capabilities and hardening checks.

Static PE/ELF triage in pure JS: headers, sections, entropy, imports, imphash, Rich header, overlays, TLS callbacks, packer hints (UPX, ASPack, VMProtect...), suspicious API capabilities mapped to ATT&CK, and hardening (ASLR, NX, CFG, PIE, RELRO, canary). Never executes samples. Zero deps.

Published to GitHub Packages, not npmjs.com. GitHub Packages needs a GitHub token with read:packages to install, even for public packages: add //npm.pkg.github.com/:_authToken=${GITHUB_TOKEN} to .npmrc or run npm login --registry=https://npm.pkg.github.com.

Why it exists

binary-sentinel gives an analyst a quick first look at a Windows PE (EXE/DLL/SYS, 32- and 64-bit) or Linux/Unix ELF file without leaving the terminal or CI. The same parser can also check your own release binaries for missing hardening (ASLR, DEP/NX, CFG, PIE, RELRO, stack canaries). Samples are only ever read as bytes and are never executed or loaded.

CLI, library and GitHub Action. Node.js 18+, zero runtime dependencies, no native code.

Features

packer-section

Section names of UPX, ASPack, PECompact, MPRESS, NsPack, Themida/WinLicense, VMProtect, Enigma, Petite, FSG, MEW, Obsidium and more (default: high)

packer-signature

Packer/protector strings (UPX!, PECompact2, ConfuserEx…) (default: high)

rwx-section

Writable + executable section or LOAD segment (default: high)

entrypoint-anomaly

Entry point outside every section, in a non-executable section or in the last section (default: high)

embedded-executable

Overlay contains another PE/ELF or archive (droppers, installers) (default: high)

injection-imports

Classic injection API combinations (VirtualAllocEx + WriteProcessMemory + CreateRemoteThread, process hollowing…) (default: high)

high-entropy-section

Executable section ≥ 7.2 bits/byte, or any section ≥ 7.6 (default: medium)

dynamic-api-resolution

Fewer than 15 imports including GetProcAddress/dlsym (default: medium)

Usage

# Example

$ npx binary-sentinel suspicious.exe

# JSON includes full headers/sections/imports

$ npx binary-sentinel ./samples --format json --json triage.json

# CI gate for your own binaries

$ npx binary-sentinel dist/ --profile hardening --fail-on high

CI / GitHub Action

permissions:
  contents: read
  security-events: write   # only for the SARIF upload
steps:
  - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4
    with: { persist-credentials: false }
  - uses: MrLouisWright/binary-sentinel@v1
    with:
      targets: 'dist/'
      fail-on: high
      sarif: binary-sentinel.sarif
  - uses: github/codeql-action/upload-sarif@v3
    if: always()
    with: { sarif_file: binary-sentinel.sarif }

FlagDescription

-f, --format <fmt>text (default) | json | sarif | markdown
--json/--sarif/--markdown <file>Also write that format to a file

--list-rulesPrint rules and default severities
